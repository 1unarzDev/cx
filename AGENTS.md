# cx implementation
Use isolated branches/worktrees under `worktrees`, verifying cwd and branch before writing. Do not recursively spawn workers. Root owns Cargo.toml, Cargo.lock, main.rs and shared protocol schemas. Keep host mutations serialized by root; workers may perform bounded read-only host checks. Never alter unrelated tmux sessions, SSH trust, provider credentials/config, WARP, or live networking. No doctor command/dashboard or terminal emulator. Do not print secrets, transcripts or unbounded environment data. Report commit, actual tests, evidence, unresolved issues, and integration requirements.

## Shared contracts
Rust modules: `model`, `transport`, `sessions`, `files`, `network`, `ui`, `store`.
Root owns `model`, `store`, `transport`, and CLI dispatch. Modules return anyhow::Result. `Device { id, name, target: Option<String>, account, host, status, observed_at }`: None target is local, remote target is an existing SSH alias or validated user@host; no agent forwarding. Status strings report evidence, not assumptions.
`Request { version:u32, id:String, op:Operation }`, `Response { version:u32, id:String, result:Option<serde_json::Value>, error:Option<String> }`. Version 1. Fixed helper `~/.local/bin/cx helper` over SSH stdin, framed `CX1 <length>\n` plus JSON; 1 MiB max. Startup noise bounded, no arbitrary remote command interpolation.
Operation variants defined in model.rs. Module entrypoints `sessions::list() -> Result<Vec<Session>>`, `sessions::create(&CreateSession)->Result<Session>`, `sessions::attach(&Device,&Session,bool)->Result<()>`; `files::handle(&Operation)->Result<Value>`; `network::observe()->Result<Value>`; `ui::run()->Result<()>`. UI uses transport::request(&Device,Operation), store::devices()/save_devices(), sessions::attach(). Root handles remote helper deployment and CLI integration. Shared schemas frozen after live slice; coordinate changes first.
